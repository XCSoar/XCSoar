---
title: Configure Devices
description: Configuring the ports, baud rates and drivers of the GPS and other devices connected to XCSoar.
---

The Devices page is used to specify the ports used to communicate with the GPS
and other serial devices. The default settings are COM1 and 4800 bits per
second. When connected to the Vega intelligent variometer, the settings should
be COM1 and 38400.

`Config 2/3` → `Devices`

Four devices can be configured (device A through D). One, for example, can be
connected to a GPS and another to a second device such as a variometer. If there
is no further device, set the unused ports to `Disabled`. XCSoar will then
ignore those ports.

![Devices configuration](/img/figures/config-devices.png)

COM ports 0 to 10 may be used, including a TCP/IP connection. Which COM port is
appropriate for you depends on what brand of PDA you use, and the communications
medium (serial cable, Bluetooth, virtual COM port, SD card or CF based GPS,
internal GPS). Detailing the various options for different devices is beyond the
scope of this document. If you have trouble identifying which COM port to set,
please refer to the XCSoar website and mailing lists.

::field-group
  :::field{name="Port"}
  This setting maps an existing interface (port) of your glide computer to one
  of the available slots A to D.

  On Android, Bluetooth LE devices appear as `BLE port` (a serial UART used by
  varios such as BlueFly) or `BLE sensor` (heart-rate monitors, pulse oximeters,
  SensBox, and engine sensors). A BlueFly Vario must be selected as `BLE port`
  with the BlueFly driver; `BLE sensor` cannot carry its serial protocol.
  `Engine Type` appears only for an engine-sensor BLE device (ignition scaling);
  heart-rate bands do not show it.

  A Xiaomi Smart Band talks GATT on a random LE address; XCSoar follows that
  live device. Enable `Heart rate broadcast` and leave the Xiaomi app (and a
  second XCSoar copy) disconnected so the standard heart-rate service is free.

  A pulse oximeter is selected as `BLE sensor` as well. The Blood Oxygen InfoBox
  shows its saturation. The Devices list shows `Heart Rate`, `Pressure`,
  `Temperature`, and `Relative humidity` among the other sensor flags, and
  `Battery=N%` when remaining charge is known, including BLE sensors that expose
  the standard heart-rate, Environmental Sensing, and Battery services.
  :::

  :::field{name="Baudrate"}
  Set this to the communication speed of the connected device.
  :::

  :::field{name="TCP Port"}
  This setting is useful to e.g. connect to the Condor flight simulator and do
  some XCSoar training in winter time.
  :::

  :::field{name="Bulk baud rate"}
  The baud rate used for bulk transfers, such as task declaration or flight
  download. The item is visible for those devices that support the feature.
  :::

  :::field{name="Driver"}
  The specific type of device can be selected from a list in order to enable
  support for devices with proprietary protocols or special functions.
  :::

  :::field{name="Sync. from device*"}
  This option lets you configure if XCSoar should use settings like the
  MacCready value, bugs and ballast from the device.
  :::

  :::field{name="Sync. to device*"}
  This option lets you configure if XCSoar should send settings like the
  MacCready value, bugs and ballast to the device.
  :::

  :::field{name="Ignore checksum*"}
  If your GPS device outputs invalid NMEA checksums, this will allow it’s data
  to be used anyway.
  :::
::
